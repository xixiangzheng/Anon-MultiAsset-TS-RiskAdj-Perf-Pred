# 下一步计划

> **基线锚点**：公榜 0.00313173 / rank 71（2026-08-09，详见《lightgbm_baseline_验证》§7）
> **目标**：冲进 0.004+（约前 10）。弱信号赛题、分布压缩，小幅 Δ 即大幅跳排名
> **原则**：始终用 purged 时序 CV 衡量 Δ；只提交 CV 明确正向的改动（公榜 5 次/日，勿追公榜噪声/过拟合）

## 总策略：小数据快迭代 → 仅对胜出配置全量训练

baseline 全量训练在 load~110 争抢下耗时 10h33m。为避免每次迭代都付这个成本：

1. 开发一律先在 `/tmp/lgbm_tinydata`（1 分区）或 `--max-train-rows` 子采样上验证 Δ
2. 对照基线在**同一 CV 折**上的 oof（基线 0.00209）看增量，排除折间随机性
3. 只有 CV 明确正向的改动，才挑机器空闲时段全量训练 + 提交

## 优先级（按性价比从高到低）

### P0 · 利用 responder（baseline 完全没用，最大低垂果实）
47 个 responder 仅训练可见、测试不可见，但**可由 features 预测**。可行路径：

- **Stacking（推荐先做）**：stage1 训 `feature→responder` 模型；用其 OOF 预测作为 stage2 target 模型的**额外特征**；推理时 stage1 先预测 responder 再喂给 stage2。完全合规、可复用现有 LGBM 流水线
- **目标去噪/重加权**：用与 target 高相关的 responder 构造更干净的目标，或对 target-responder 不一致的样本降权
- **多任务（NN 路线）**：共享表征联合预测 target+responders，更自然在神经网络里实现

**第一步**：分析哪些 responder 与 target 相关性最高 → 选 top-K 做 stacking 小数据验证。

### P1 · 扩展因果历史特征
- 更长滚动窗口（10/20/60）捕捉不同周期
- 跨标的特征（每个 time_id 内的截面排名、相对强度）
- 波动率类（滚动 std、波动比、极值比）
- top-K 历史特征从 48 扩到 100+

### P2 · 模型集成（多样性降方差）
- LGBM + XGBoost + CatBoost（不同 GBDT 去相关）
- LGBM + 神经网络（MLP/TabNet）多样性
- 在现有 3-seed bagging 基础上加**模型类型**多样性

### P3 · 认真调参
- 4 预注册候选之外，用 Optuna 在 purged CV 上搜（num_leaves / lr / min_data / reg / bagging 等）
- 严守：只用 development 折调参，holdout 不参与选参

### P4 · 推理向量化（合规性，非提分）
`main.py` 的 per-row 历史循环向量化，降推理耗时（当前已合规，低优先）

## 纪律红线（防过拟合 / 防泄漏）

- **严禁未来信息**：所有特征只用当前及历史；标准化/切分按 `time_id`，不得用未来分布
- **验证只用 purged 时序折**；holdout 全程只看一次，不参与选参
- **不追公榜噪声**：每天 5 次提交用在 CV 验证过的改动上，避免在公榜上反复试错过拟合
- **改动都先小数据 Δ 验证再全量**
