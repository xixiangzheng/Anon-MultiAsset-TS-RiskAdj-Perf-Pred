## 1. Python 环境

系统 `python3`（3.12.3）自带的 pandas 已损坏（C 扩展未构建，且 numpy 2.5 与赛事固定版本不兼容）；系统缺 `python3.12-venv`/`ensurepip`，且无免密 sudo。服务器无外网，仅 USTC 镜像（`mirrors.ustc.edu.cn`）可达。

**解决方案**：在项目根建独立 venv（`.venv`，已 gitignore），用 `--without-pip` 创建，再借系统 pip 的 `--python` 选项引导 pip：

```bash
python3 -m venv --without-pip .venv
python3 -m pip --python .venv/bin/python install --upgrade pip setuptools wheel \
  -i https://mirrors.ustc.edu.cn/pypi/simple
.venv/bin/python -m pip config set global.index-url https://mirrors.ustc.edu.cn/pypi/simple
.venv/bin/python -m pip install "numpy<2" pyarrow scikit-learn polars lightgbm "pandas==2.2.3"
```

依赖版本（cp312 现代版本；赛事 pinned 旧版本无 cp312 wheel，故放宽）：

| 包 | 版本 | 说明 |
|---|---|---|
| numpy | 1.26.4 | <2，兼容示例代码 |
| pandas | **2.2.3** | 见下「pandas 版本」说明 |
| pyarrow | 25.0.0 | 读 parquet |
| scikit-learn | 1.9.0 | linear baseline 的 Ridge |
| polars | 1.43.2 | data_io 示例 |
| lightgbm | 4.7.0 | lightgbm baseline |

**pandas 版本踩坑**：初装 pandas 3.0.5，随机基线可跑通；但 linear baseline 在 `fit_standardizer` 崩溃——pandas 3.0 默认 Copy-on-Write 下 `Series.to_numpy()` 返回**只读**数组，`train.py:91` 的原地赋值 `scale[...]=1.0` 抛 `ValueError: assignment destination is read-only`。已降级至 **2.2.3** 规避（亦更贴近赛事 pinned 的 pandas 2.0.x）。

使用：`source .venv/bin/activate`，或直接 `/mnt/iscsi/hd/xxz/.venv/bin/python`。
本地测试线程数限制 ≤4（`OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 MKL_NUM_THREADS=4`）。

## 3. 随机基线 random_strategy

全量训练 + Time-Series API 推理。

**训练**（`examples/random_strategy/train.py`）：耗时 2m20s
- train_rows=10,604,337 / valid_rows=2,623,355
- prediction_scale=0.05491（训练集 target 加权标准差 ×0.05）
- valid_zero_score=0.0（全零预测 = 0 分基准，符合加权零均值 R²）

**推理**（`timeseries_api/run_timeseries_api.py`）：耗时 3m42s

| 指标 | 实测 | 限制 |
|---|---|---|
| status | ok | — |
| rows | 3,217,458 | = 测试集 |
| predict_calls | 214,538 个 time_id | — |
| model_init | 0.002s | ≤180s |
| 单步平均 | 0.178ms | ≤50ms |
| 单步最大 | 5.1ms | ≤50ms |
| 超时次数 | 0 | — |

输出 `/tmp/random_submission.csv`：3,217,458 行，全有限浮点，0 空值，std≈0.055（≈scale）。

**结论**：环境与 Time-Series API 全链路打通；随机基线得分 ≈0（即零基准）。

## 4. 线性滑窗基线 linear_window_strategy

Ridge（lsqr，alpha=1.0）+ 每标的滑动均值（window=5）；特征 = 323 原始 + 323 滚动均值 = 646 维，标准化后加权拟合。

**训练**（`examples/linear_window_strategy/train.py`）：耗时 ~43 min，峰值 RSS ~261GB
- train_rows=10,604,337 / valid_rows=2,623,355
- **train_score = +0.00258**（训练集微弱正信号）
- **valid_score = −0.00553**（验证集为负）

> 耗时主因：全量数据 float64 化 + 646 维矩阵构造 + Ridge lsqr 在千万级系统上单线程迭代；内存峰值源于多层 copy 未及时归还。

**推理**（`timeseries_api/run_timeseries_api.py`）：耗时 12m57s

| 指标 | 实测 | 限制 |
|---|---|---|
| status / rows | ok / 3,217,458 | ✅ |
| model_init | 0.005s | ≤180s |
| 单步平均 | 2.56ms | ≤50ms |
| 单步最大 | 3.04ms | ≤50ms |
| 超时次数 | 0 | — |

输出 `/tmp/linear_submission.csv`：3,217,458 行，全有限浮点，0 空值；尾部较宽（min/max ≈ ±1.7，线性放大所致）。

**关键发现**：简单线性模型在验证集 **valid_score=−0.0055 < 0**，即样本外表现**劣于全零基线**（随机基线 valid=0.0）。说明在匿名金融特征上，朴素线性 + 滚动均值不足以提取可用信号，存在过拟合。后续需更强模型（如 lightgbm_baseline）与防过拟合手段（purged CV、正则、降噪）。
