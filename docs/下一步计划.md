## 总策略：小数据快迭代 → 仅对胜出配置全量训练

baseline 全量训练在 load~110 争扰下耗时 10h33m。为避免每次迭代都付这个成本：

1. 开发一律先在 `/tmp/lgbm_tinydata`（1 分区）或 `--max-train-rows` 子采样上验证 Δ
2. 对照基线在**同一 CV 折**上的 oof（基线 0.00209）看增量，排除折间随机性
3. 只有 CV 明确正向的改动，才挑机器空闲时段全量训练 + 提交

## 优先级（v2，按性价比从高到低）

### P0（新）· 特征工程——捕捉 target 本身的可预测成分
target 是 innovation，可预测成分极弱但存在。重点挖：
- **更长/多尺度滚动窗口**（10/20/60）捕捉不同周期
- **跨标的截面特征**（每个 time_id 内的截面排名、z-score、相对强度）——panel 数据的关键结构
- **波动率/动量类**（滚动 std、波动比、极值比、路径特征）
- **历史特征 top-K 从 48 扩到 100+**
- 验证方式：每加一组特征，小数据看 oof Δ（对照 0.002）

### P1 · 集成降方差（多样性）
弱信号下，降方差 = 稳定的小幅增益：
- LGBM + XGBoost + CatBoost（不同 GBDT 去相关）
- LGBM + 神经网络（MLP/TabNet）多样性
- 在现有 3-seed bagging 基础上加**模型类型**多样性

### P2 · 认真调参
- 4 预注册候选之外，用 Optuna 在 purged CV 上搜（num_leaves / lr / min_data / reg / bagging）
- 严守：只用 development 折调参，holdout 不参与选参

### P3（可选，低优先）· 预测 responder 作额外特征
实验显示线性组合上限仅 +0.0005，但作为**额外特征**塞进 target 树模型或许多捞一点（responder_02/03/18/19 的 OOF 预测）。低成本试一次，若 oof 无明显正向即弃。

### P4 · 推理向量化（合规性，非提分）
`main.py` 的 per-row 历史循环向量化，降推理耗时（当前已合规）
